通知渠道配置外部推送服务，在控制面板“个人设置 - 通知渠道”管理，可被多条业务引用；不设启用开关，可用性由[测试发送](/docs/api/channel/test)验证。

```prisma
model notificationChannel {
  id          Int                @id @default(autoincrement())
  name        String // 渠道名称，后端保证唯一（DB 不设 unique）
  type        String // 渠道类型唯一键
  config      String             @default("{}") // JSON 字符串，存该渠道除 type 外的全部参数
  create_time DateTime           @default(now())
  update_time DateTime           @default(now()) @updatedAt
  messageAlertLinks messageAlertRuleChannel[]

  @@index([type])
}
```

### 字段说明

| 字段 | 说明 |
|------|------|
| name | 渠道名称，trim 后非空、≤ 50 字符、全局唯一 |
| type | 渠道类型唯一键，取值 `bark`、`dingding`、`discord`、`feishu`、`googlechat`、`gotify`、`kook`、`pushplus`、`serverchan`、`telegram`、`webhook`、`wecomapp`、`wecombot`、`wpush`、`wxpusher` |
| config | 渠道配置，JSON 字符串。支持对象或 JSON 字符串提交，后端按渠道类型白名单清洗（未声明字段丢弃，跨渠道通用配置 `general` 除外）后落库 |

### 通用配置

除各渠道专属字段外，每个渠道的 `config` 都可携带一个可选的 `general` 对象，用于跨渠道通用配置。后端保存时统一清洗（`footer`、`messageTemplate`、`proxy` 一律 trim、缺省空字符串），无论前端是否提交都会写入。

      description: 'HTTP 代理地址，格式 `host:port` 或 `http://host:port`（协议可省略，默认 `http`），仅 HTTP 类渠道生效（`apprise` 走 CLI 不适用）',
