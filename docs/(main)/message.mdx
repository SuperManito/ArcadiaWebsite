消息中心用于集中接收和管理平台与各业务产生的消息，你可以把业务通知推送到这里，在控制面板统一查看和处理。

- 消息长度上限为 `标题 200 字符` `内容 20000 字符`，超出部分自动截断，不会拒绝发送。
- 分类、级别、标题、内容都相同的消息，30 秒内只保留一条，避免同一事件反复刷屏。

## 通知渠道

通知渠道用于对接外部的推送服务，在控制面板“消息中心 - 渠道管理”中创建和管理，配置好的渠道可以先发一条测试消息确认能否正常送达。

### 渠道频率限制

各推送服务方都限制了接口的调用频率，平台按渠道类型内置了对应的上限。超过上限的推送不会丢弃、只延后发出，负责排队限速的是下面[节流队列](#节流队列)一节介绍的内置机制，而只有监控告警的告警推送会进这个队列，渠道的测试发送点了就直接发出。各渠道的频率限制如下：

| 渠道 | 频率限制 |
| --- | --- |
| 钉钉 | 20 条/分钟 |
| Discord | 5 次/2 秒 |
| 飞书 | 5 次/秒，且 100 条/分钟 |
| Google Chat | 60 次/分钟 |
| KOOK | 60 条/分钟 |
| pushplus | 5 次/分钟 |
| QQ 机器人 | 30 条/分钟 |
| Server 酱 | 5 条/分钟 |
| Telegram | 1 条/秒 |
| 企业微信机器人 | 20 条/分钟 |
| WxPusher | 2 次/秒 |

其余渠道没有明确的官方频率限制，按平台内置的保守默认值发送。

## 监控告警

监控告警会检查每一条进入消息中心的消息，命中规则后自动通过通知渠道推送告警，规则在“消息中心 - 监控告警”中管理。

功能由 **通知渠道** 与 **告警规则** 两部分组成：

- **通知渠道**：对接外部推送服务（如 Bark、钉钉）的统一配置与管理，支持连接测试与通用消息模板，详见上方[通知渠道](#通知渠道)。
- **告警规则**：定义**什么消息需要告警**以及**告警到哪里**。先用消息 **分类**（如定时任务、系统事件）与 **级别**（信息、警告、错误、成功）圈定要监控的消息范围，再对 **标题 / 内容** 设置匹配条件；条件支持文本包含、正则等多种匹配方式，可“满足全部”或“满足任一”组合，命中后发往规则关联的一个或多个通知渠道。

一条消息可以同时命中多条规则，每条规则关联的全部渠道都会各发一份，单个渠道发送失败不影响其余渠道。

告警规则分两类：

- **全局规则**：命中后把这条消息推给规则关联的所有渠道。
- **一对一规则**：不单独触发，需要关联全局规则。关联的全局规则命中后，按收信人名单逐行匹配消息正文，每个人只收到与自己相关的那几行，还能单独设置匹配方式、消息标题和推送渠道。

### 节流队列

从渠道发出去的告警分两种，实时性不一样，先分清楚：

- **监控告警的告警推送**：你在“消息中心 - 监控告警”配置规则，规则命中消息后发出的告警，这种推送要进节流队列排队。
- **其它业务自带的告警通知**：目前指定时任务的失败通知，在任务里直接选好通知渠道，任务一失败就即时发出、不进队列；它只把这次发送计入渠道的频率额度，避免大批任务同时失败时把渠道打爆。

监控告警的告警推送由内置的**节流队列**（Channel Throttle Queue）统一调度：它按渠道类型把待发告警排成队伍，再按各渠道的频率限制依次发送——就像车站排队检票，队伍再长也不会丢票，只是晚一点上车。

- **正常情况下都是即时的**：消息进入消息中心后马上排队，渠道还有额度时几乎感觉不到延迟，只有短时间告警量超过渠道速度才会积压。
- **全局规则优先插队**：全局规则的告警插到对应渠道队伍的最前面，先于一对一规则的告警发出，正常负载下与实时推送没有差别；一对一规则的告警排在常规队列中，只在积压时延后。
- **只延迟，不丢弃**：积压多少条都会发出去，只是到得晚，渠道繁忙时延迟数秒到几分钟属正常现象。队列只保存在内存中，服务重启时还没发出的告警会一并丢失。
- **积压有提醒**：某一类渠道积压超过 1000 条时，服务端日志记录一条警告，提示需要关注渠道速度或精简告警规则，不影响发送。
- **失败不重试**：每条告警只尝试发送一次，同一条消息的全部失败会汇总成一条站内消息，便于集中排查。
- **不影响消息记录**：消息是先保存进消息中心、再在后台匹配和推送告警的，渠道再忙再慢，也不会让消息存不进来或看不到。

    调用 `push(title, content, type)` 推送消息：

    | 参数 | 必填 | 说明 |
    |------|------|------|
    | title | 是 | 消息标题 |
    | content | 是 | 消息内容 |
    | type | 否 | 消息级别，默认 `info`，可选值：`info`、`warn`、`error`、`success` |

    推送成功返回 `true`，失败抛出 `Error`。

    其它语言建议直接用下方的本地 HTTP 请求方式。
